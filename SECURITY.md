# Security policy

This is beta software. Supported fixes target the latest beta; no production SLA
or security certification is provided. Do not expose the local dashboard publicly
without authentication and an appropriate deployment boundary.

For a suspected vulnerability, use GitHub private vulnerability reporting when
available or request a private contact from the maintainer without posting exploit
details, credentials or private data in a public issue. Never paste access tokens.

Contracts are trusted local configuration. Only public HTTPS data is intended for
the example monitor. Hashes detect accidental corruption, not an administrator
who can replace content and hashes. Storage and replay verification have separate
documented scopes. Back up state before migrations or manual approvals.
